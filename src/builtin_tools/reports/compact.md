# Compact Tool — Implementation Report

## Ported to C++

All CPU-bound / decision kernels from `plans/compact.md` §3 are implemented in
`src/builtin_tools/compact_tool.h` and `src/builtin_tools/compact_tool.cpp` in
namespace `kimix::builtin_tools::compact`.

- Message representation (`message`, `content_part`) and helpers (`extract_text`, `has_think_part`, `is_user_or_assistant`).
- `CompactMode` / `compaction_options` / `parse_compact_mode` / `mode_guidance`.
- `should_auto_compact` — auto-trigger budget logic with saturating `int64_t` arithmetic.
- `adaptive_preserve_depth` — last-turn heuristic preserve depth (ASCII-only).
- `detect_cascade_depth` — counts compaction-summary markers.
- `build_compaction_prompt` — prompt text assembly (cascade selection, mode guidance, decision sections, custom instruction).
- `build_compact_message_text` — legacy flattened compact message text.
- prepare_compaction_input — history slicing + prompt/compact_message assembly.
- compute_surface_fingerprint — cheap surface snapshot with injectable token counter.
- estimate_text_tokens / estimate_message_tokens — language-aware token heuristic.
- message_tool_call_delta / balanced_cut_indices / nearest_balanced_cut_before — the
  tool-pairing fold (kimi_cli/soul/tool_pairing.py).
- resolve_preserve_split — SimpleCompaction.prepare's preserve boundary (Phase-6 primacy
  re-insertion and its re-cut included); see "Tool pairing / preserve boundary" below.
- Compact — thin kimix::builtin_tools::Tool subclass for Python binding integration.

Stayed in Python

- LLM summarization, durable ledger I/O, stability/shrink checks, todo injection formatting.
- Soul / session state, context-overflow force-compact loop, provider overflow marker classification.
- Exact tiktoken counting.
- Pydantic validation and tool orchestration (src/kimix/tools/context/__init__.py).
- Compaction prompt prose source of truth (kimi-cli/src/kimi_cli/prompts/compact.md, compact_cascade.md).

Deviations

- ASCII-only lowercasing in adaptive_preserve_depth; relevant keywords are ASCII.
- Token estimation is heuristic-only; injectable counter lets Python supply tiktoken counts.
- prepare_compaction_input keeps the narrow "already balanced, contiguous index" contract.
- Non-text/non-think content parts collapse to type == "other" with empty text in the
  Compact Tool-class path (the runtime_py binding passes the raw type string through;
  both are ignored by the assembly kernels).
- todos_max_items is carried but not enforced by C++ kernels.

Tool pairing / preserve boundary (now ported)

The soul-level boundary was originally left to Python; it is now in C++ because
`src/agent/soul.cpp` needs it and the reference behaviour turns out to matter:

- `message_tool_call_delta` / `balanced_cut_indices` / `nearest_balanced_cut_before`
  (kimi_cli/soul/tool_pairing.py) — the fold that decides which cut indices leave no
  unanswered tool call behind.  `nearest_balanced_cut_before` mirrors the reference's
  clamp-first order: an out-of-range index returns the clamped value *without* running
  the fold (so an unbalanced history only raises/reports for an in-range index).
- `resolve_preserve_split` (SimpleCompaction.prepare, compaction.py:711-772) — the
  preserve-depth walk over user/assistant messages, the balanced-cut snap, the Phase-6
  primacy re-insertion of `messages[0]` and the re-cut that follows it (which drops the
  primacy copy again and can leave `messages[0]` in the compacted region only).
  `preserve_split` expresses both reference tail shapes with `preserve_start_index` +
  `keep_first_message`; the `recut_fallback` branch is reachable in neither
  implementation (cut 0 always exists below a non-zero preserve point).
- Because this build has exceptions disabled, an unbalanced history (reference:
  `ValueError` out of `prepare`) is reported as `unbalanced = true` + `compact = false`
  instead of aborting.

Verification: tests/unit/builtin_tools/test_compact_tool.cpp replays
tests/unit/builtin_tools/tool_pairing_goldens.inc (61 histories, 728 nearest-cut and 610
split vectors, generated by scripts/gen_tool_pairing_goldens.py --check from the real
reference, which also cross-checks the generator's own mirror), and
python/tests/test_parity_tool_pairing.py drives the same kernels live through the
runtime_py bindings over that corpus plus a fresh seeded fuzz.

Parity fixes (differential verification pass)

Four port-only behaviours were found by `python/tests/test_parity_compact.py` (live
 differential harness against the kimi-agent checkout) and fixed:

- `should_auto_compact`: removed an undocumented `max_context_size <= 0` early return.
  The reference (`compaction.py:269-278`) evaluates both comparisons unconditionally, so a
  zero/negative window reports "compact" for every non-negative token count; the port
  returned `false`.  Regression tests: `should_auto_compact_zero_or_negative_max_context`
  in `tests/unit/builtin_tools/test_compact_tool.cpp` and
  `test_should_auto_compact_zero_or_negative_window` + `test_should_auto_compact_fuzz` in
  the parity test.
- `adaptive_preserve_depth`: the two early returns (empty history / no user-or-assistant
  turn) now return `min_preserved` *unclamped*, exactly like `compaction.py:299` / `308-309`;
  the signal path still clamps to `[min_preserved, max_preserved]`.
- `compute_surface_fingerprint`: `last_message_text` is now engaged for every non-empty
  history (a last message without text parts yields `""`, not `nullopt`) — the reference
  mirrors `None` only for an empty history (`compaction.py:183-190`).
- `runtime_py` binding: `throw_tool_error` (`src/runtime/py/py_builtin_web.cpp`) no longer
  throws a bare `std::runtime_error`, which this build's pybind11 3.0.2 default translator
  does not translate: Python saw `SystemError: Exception escaped from default exception
  translator!` with the `tool_error` message lost (repro:
  `web.prepare_compaction_input(messages, 0)`).  It now sets `PyExc_RuntimeError` and throws
  `py::error_already_set`, so the "no messages to compact" signal arrives as `RuntimeError`
  carrying its message.

## Tests

`tests/unit/builtin_tools/test_compact_tool.cpp` covers the golden vectors from
`plans/compact.md` §6 using Boost.UT; the reference-derived vectors for the kernels
`runtime_py` does not expose (`adaptive_preserve_depth`, `detect_cascade_depth`,
`compute_surface_fingerprint`, `estimate_text_tokens` / `estimate_message_tokens`) were
regenerated from `kimi_cli/soul/compaction.py` + `kimi_cli/utils/tokens.py` (a.k.a.
`kimi-cli/tests/core/test_adaptive_preserve.py`, `kimi-cli/tests/utils/test_tokens.py`).

`python/tests/test_parity_compact.py` holds the live differential harness:
`should_auto_compact` (reference suite + boundary sweep + seeded fuzz), `extract_text` /
`has_think_part` / `is_user_or_assistant`, `build_compaction_prompt` /
`build_compact_message_text` over the real `prompts.COMPACT` / `COMPACT_CASCADE`, and
`prepare_compaction_input` (slice parity, text assembly, byte-exact comparison with
`SimpleCompaction.prepare` wherever its split is contiguous, session simulation, Phase-6
shape characterisation).

Target name: `test_builtin_compact`.
